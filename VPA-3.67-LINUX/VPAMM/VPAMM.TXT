VPA "Mixed Mode"
================

VPAMM is a shotgun port of VPA 3.61 to the PCC runtime library
(graphics and DPMI loader). The code is approx. PCC 1.1.4; the SVGA
driver configuration is not yet available to users and remains at
conservative values (no LFB, no modeline programming).

Why is this necessary? Stock VPA 3.61 (Borland DPMI loader,
Uz's SVGA driver) does not run on my Win95, but PCC does -- and
so does VPAMM. Maybe it helps any of you with a Laptop problem.
It is called "mixed mode" because, like PCC, it can run in
real or protected mode. It'll usually do the latter. If your VPA
crashes on a big database, VPAMM may also be a solution, because
it uses a more robust memory allocator (equally safe as 3.51's).

Invoke it normally, either with /s or without. If you don't run
it from Windows, "dpmi16bi.ovl" must be in the same directory
as vpamm.exe.

I think the program is now fairly stable. The most obvious problem,
rounding errors, should be fixed now. Graphics throughput might be a
bit lower than original VPA, but I doubl you notice this.

Note that the "free memory" display is worthless in VPAMM. Actually,
all "free memory" displays are worthless, because they're obsolete
by the time you read them.

When this program crashes it writes a core dump ("vpacore").
That file can help developers find the place where it crashed.


  --Stefan


Notes for programmers: I have integrated this in the main VPA makefile;
"make vpamm.exe" should compile everything for you. You need to get
D4TP separately, and configure the path in the makefile.

Note 2: don't take the comments too serious. I was 14 when I wrote the
graphics library :-)
